# Security reporting

Do not attach private recordings, animal/cohort metadata, credentials or complete
machine logs to public issues. Remove personal paths and identifiers from shared
examples and prefer a small synthetic reproduction.

Once the repository is published, use GitHub's private vulnerability reporting
feature if the maintainer has enabled it. Otherwise contact the maintainer
privately to arrange a report; do not post exploit details or sensitive files in
a public issue. The maintainer must select a private contact method before
publication. No response-time commitment is made by this document.

Version 1.0.0 is the initial public release line. Camera SDKs, USB/GPU drivers,
FFmpeg and firmware are external components; include their versions when they
are relevant to a report.
